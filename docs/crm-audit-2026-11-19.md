# CRM friction and acquisition audit — 19 November 2026

The release focuses on protecting work during asynchronous actions and making the next acquisition step clear.

| Finding | Resolution |
| --- | --- |
| Typing while Save draft was pending could mark newer, unsaved text as saved | Compare against the submitted snapshot; retain newer edits as unsaved and prevent Save-and-continue from leaving them behind. |
| A second navigation could overwrite an unresolved unsaved-work prompt | Retain the first choice; ignore duplicate navigation and cancellation while its save runs. |
| Replacing a CSV or changing its defaults could import the previous preview | Invalidate old rows and in-flight previews; require another preview. |
| CSV import omitted the confirmed booker-name field | Preserve `booker_contact_name` without promoting an imported contact to verified. |
| A confirmed booking-team route was treated as a named decision-maker | Require both booking-role confirmation and an actual name for the named-booker filter. |
| Old dates kept rejected, uninterested or booked leads in follow-up queues | Exclude inactive acquisition records; surface replies and paused outreach correctly. |
| A connected mailbox could enable Send with no recipient address | Require a valid lead email before enabling the control; server checks remain authoritative. |
| Media library unnecessarily queried mailbox status | Load the independent asset library without that mailbox dependency. |
| Accepted YouTube Shorts/live links had no usable preview | Support those video paths and provide an explicit explanation for non-embeddable channel links. |
| Campaigns required opening individual leads from the full list | Add campaign drilldown, readiness counts, combined owner/status/search filters and direct next-action controls. |

## Verification and limits

117 automated checks cover the existing permission boundaries, database workflows, calendar, mail MIME handling and new UI regressions. The database reported ACTIVE_HEALTHY. A bounded last-24-hour log aggregate returned no ERROR/FATAL severity entries; this is not a guarantee that every request succeeded. Authenticated browser checks and deployment evidence are recorded with the release outcome.

Email delivery, receiving and cross-posting require their pending provider/account connections. Test transports do not establish live SMTP or social delivery. No test emails, calls, bookings or fabricated activity were created in production.
